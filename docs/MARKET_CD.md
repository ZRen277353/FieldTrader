# C/D 与 E 只读验证

本次沿用原 .NET 8/WPF、PythonVisionPipeline、MarketWorkflow、SQLite 和模拟鼠标接口。未改音频识别、混音或播放实现。真实交易提交没有实现或启用；现有 Windows 导航适配器仍默认关闭。

## C：整套配方与特殊商品分析

`TradingDomain.cs` 定义 ExchangeRecipe、RecipeMaterial、InventoryLot、FeePolicy、TradingPolicy、TradeDecision、ResaleRule。`TradingStore.cs` 将 SQLite 升至 4，增加 ExchangeRecipes、ExchangeRecipeMaterials、TradingDecisions、SimulationState、SimulationLedger。

配方需人工核验来源和剩余次数。网站种子仅作目录与参考价，不能代替配方、库存、时段观察或成交凭证。没有预置真实游戏配方。本批截图没有联络人兑换页，未实现从这些图片凭空推断配方。

决策先算整套材料需求，扣除有来源及成本的现有库存，再按当前有效报价补缺口。预计单价取当前游戏观察价格与历史 P25 较小值，并按可配置折扣保守下调。已累积至少 3 个真实成交样本时优先用成交分布，否则用实时市场卡片分布；最低样本数仍由策略检查。费用包括兑换费、每批管理费、成交费和风险预留，各批分别向上取整。未核验费率、过期报价、数量不足、预算不足或利润不足均 SKIP。预测价格与上架页的显示价格是不同概念，后者必须再次校验。

`TradingAnalysis` 缓存价格，在材料或成品更新后重评关联配方，持久化 BUY/EXCHANGE/SKIP。兑换完成后模拟账本生成 SELL 事件。BUY 决策给 MarketScheduler 提供材料优先级，仍保留原有最大未巡查时长。完整多队列任务优先级不是本次 C/D 的已验收内容。

子弹和钥匙只有逐商品 `ResaleRule` 资格与凭证齐全才能进入独立分析。买入价和出售价分别缓存；模拟直接路径不经过联络人，普通市场采购批次不能因此获得转售资格。

## D：可持久化的隔离模拟

`TradingSimulation` 接受已评估方案。提交前验证页面、商品、按钮、时间、数量、预算；先把 Pending 与操作 ID 事务持久化，再调用原 SimulatedMouseExecutor。步骤后要独立 TradeProof，才能更新现金、数量和账本。缺证、金额/商品不符、超时或提交后取消进入 UNKNOWN；重启仍冻结。Reconcile 只核对原步骤，绝不再次点击。

SimulationRunner 的完整兑换预演和浏览导航共用会话互斥门；单步输入与截图另有共同互斥门。声音线程不参与这些门。界面也阻止采集和预演同时启动。

本次生成的成品批次独立保留，不能挪用已有同类成品。上架 1–5 件，按批次扣一次额度。已上架只记录管理费支出，实际销售收益只在模拟成交确认时记录。到期返库存，不返额度或管理费；再次出售需重新核验资格。已用周额度和总上限必须分开，600/1200 为用户提供规则，实际剩余优先读界面。本地 ISO 周键仅用于拒绝跨周陈旧截图，不自动猜测游戏刷新时刻。

模拟预测器会合成“采购成功、兑换成功、挂单和成交”凭证，以检验业务逻辑。这些不是游戏操作结果。模拟账本与真实行情样本分开，截图不会自动变成交易凭证。测试配方、费率、库存只在独立测试库里生成。

## 截图解析和界面

`TradeScreenReader` 解析购买结果、价格变化拒绝、已用额度、出售两类费用和挂单列表。商品名称通过区域几何关联，数量不能由金额反推。仓库 OCR 名称仅作为存在候选；14 类 YOLO 是 UI 类别，未证明可识别任意具体物品边界。

`vision_worker.py` 继续加载本地 best.pt 和 PP-OCRv4。对小号输入框补充放大区域 OCR，并保留原图坐标和置信度；数量识别没有填默认值。没有下载、训练或导出模型。

市场窗口新增“兑换分析与模拟账本”：导入配方、费用与预算；导出未验证录入模板和商品 ID 目录；查看当前页费用/额度/拒绝信息；预演所选配方或特殊规则；运行隔离模拟回归；沿用紧急暂停。配置默认预算 0、费用未验证、无真实配方，因此不会凭网站初始价自行采购。

## 可复现入口

`MarketReplay --stage-cd-test <out>`：34 项业务与异常模拟回归。

`MarketReplay --cd-vision <config.json> <images> <out>`：实际模型回放，输出截图证据、字段与耗时。WPF 应用支持同名两个参数入口。

`MarketReplay --stage-ab-test <out>`：44 项 A/B 与种子导入回归。`--test` 保留原模拟核心验证。

WPF `--market-integration-test <config> <images> <out>`：合成声音经过真实 RecognitionPipeline/LiveVoiceMix，同时执行实际视觉推理；不操作物理音频设备。`--self-test` 保留原应用 40 项自检。

`tools/PortableLauncher.cs` 用系统已有 .NET Framework 编译，只启动已准备好的私有 .NET 8 运行时和 WPF DLL；不调用命令壳、不安装运行时、不改系统环境。

## E 验收边界

2026-10-21 用户打开国服并人工导航，已验证应用自己的实时截图→YOLO/OCR→SQLite 链路：空收藏页以及军用杂物列表。商品列表取得 13 个名称/价格；其中 8 项匹配已知目录，5 项保持待确认。已复制只读数据库快照用于检查去重；实时记录不伪装成成交。桌面工具曾尝试展开分类但页面无变化，停止重试。未验证应用的真实鼠标导航，更未验证购买、兑换、上架、领取或成交。

国服官方版主发布的[负面清单](https://www.taptap.cn/moment/728290795337025968)涉及违规脚本处罚，没有找到自动交易获准依据。遵守用户先前的“规则允许且明确授权后再提交”条件，真实提交保持关闭；无注入、隐藏、验证码处理或反作弊规避。

后续真实业务验收还需要：联络人及完整配方页/限制页、兑换前后结果、出售资格及可操作数量、推荐价刚打开时的证据、能唯一关联物品/数量的上架结果、成交/到期页面、周额度刷新语义。购买结果小号 x1 在本批图中置信度不足；第 9 张额度变为 512 不能单独证明座钟挂单成功。必须补独立证据，不能通过放宽校验“完成”自动交易。
